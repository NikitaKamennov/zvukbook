# Windows: запуск и пересборка Звуккниг

Выпуск **0.2.0**: установщик и автономный ZIP, выбор CPU/NVIDIA в интерфейсе.
Рабочий комплект полной версии: `.local-data\windows-x64\dist\Zvukbook\` в корне проекта.
Запускай **`Zvukbook.exe`** двойным щелчком. Python, PyTorch, модель, FFmpeg,
OCR/DjVu, собственный WebView2 и Microsoft Visual C++ DLL лежат рядом:
переносить один EXE без папок нельзя.
При запуске ничего скачивать не нужно. Закрытие окна останавливает обработчики.

Переключатель **«Тёмная тема»** находится в верхней панели. Изначально тема
соответствует системной; ручной выбор сохраняется локально между запусками.
Переключаются страница, диалоги, плеер и заголовок окна Windows.
Функция действует в полной/CPU-сборке и Linux-странице. Для Windows нужна
пересборка, для Linux — перезапуск сервера и обновление страницы.

Книги, SQLite и MP3 создаются отдельно: **`%LOCALAPPDATA%\Zvukbook\library\`**.
Пересборка их не затрагивает. Linux-библиотека автоматически не переносится.
«Открыть папку MP3» показывает файлы выбранной книги. «MP3» и «ZIP» открывают
Windows-диалог сохранения. При занятом внешним плеером MP3 приложение сохраняет
новый результат и предлагает повторить только публикацию, без озвучки.

Аудио новых книг находится в
`%LOCALAPPDATA%\Zvukbook\library\mp3\Название — Автор [короткий ID]\`.
Имя закрепляется после первого успешного импорта; последующие изменения
метаданных не перемещают папку. В ней же сохраняется `cover.jpg`: встроенная
обложка EPUB/FB2/FB2.zip либо первая страница PDF/DjVu. Обложка входит в ZIP,
в сами MP3 не встраивается. Если картинка отсутствует или не читается,
приложение показывает предупреждение и продолжает импорт текста.
Для проверки нового поведения загрузи новую тестовую книгу после пересборки.
Предыдущие аудиопапки автоматически не переносятся. Подробнее —
[books-start.md](books-start.md). Изменено общее ядро, поведение действует
также в Linux после перезапуска исходного сервера.

Через **«Название, автор и обложка»** можно увидеть текущую картинку и выбрать
свою JPG/PNG/WebP до 16 MiB / 20 млн пикселей. До сохранения доступен предпросмотр
и отмена выбора. Новая обложка готовится в существующей очереди с CPU-профилем
импорта, без модели/OCR; результат появляется возле названия книги, в папке MP3
и ZIP. Готовые главы сохраняются, повторное извлечение текста не заменяет
пользовательскую обложку автоматически. После этой правки Windows пересобирается
обычной командой; функциональная проверка остаётся ручной.

Текущие форматы Windows: TXT, FB2/FB2.zip, EPUB, DOCX, PDF, DJVU/DJV.
DOC исключён из текущей спецификации по решению владельца и отложен на будущее;
LibreOffice в комплект не входит.

## Самостоятельная сборка и передача готового комплекта

Папка выпуска: `.local-data\windows-x64\release\`.

- **`Zvukbook-Setup.exe`** — один полный офлайн-установщик. Передай этот файл;
  получатель запускает его и устанавливает приложение для текущего пользователя.
  Папка — `%LOCALAPPDATA%\Programs\Zvukbook`, ярлык в меню «Пуск» и по желанию
  на рабочем столе. Права администратора не нужны. Установка/удаление блокируются
  при работающем обычном окне; книги в `%LOCALAPPDATA%\Zvukbook` сохраняются.
- **`Zvukbook-Portable.zip`** — альтернатива установщику. Нужно распаковать всю
  папку на локальный NTFS-диск в доступное текущему пользователю место и открыть
  `Zvukbook.exe`. Запуск внутри ZIP, с FAT/exFAT-флешки или из защищённого
  `Program Files` не предусмотрен: песочнице нужны корректные NTFS-права.
- `SHA256SUMS.txt`, `release-manifest.json` и `README.txt` описывают выпуск.

В обоих вариантах Python, PyTorch, OCR и системный WebView2 устанавливать не надо.
Нужные Visual C++ DLL поставляются рядом с Python/инструментами; Windows не
изменяется их отдельным установщиком. Интернет для импорта и озвучки не нужен.
Ускорение NVIDIA требует подходящего драйвера; **CPU работает без NVIDIA**.
Установщик пока без цифровой подписи.

Первая распаковка/установка и работа на другом ПК — ручная приёмка владельца.

## Облегчённая сборка: CPU, установщик и portable

Из корня проекта запусти **`build-cpu-release.cmd`** двойным щелчком.
Из Bash-терминала VS Code удобнее вызвать тот же сборщик напрямую:

```bash
powershell.exe -NoProfile -File ./scripts/build-windows.ps1 -Edition cpu -Release
```

В PowerShell:

```powershell
& .\scripts\build-windows.ps1 -Edition cpu -Release
```

После успешного завершения в **`.local-data\windows-x64\release-cpu\`** будут:

- **`Zvukbook-CPU-Setup.exe`** — офлайн-установщик.
- **`Zvukbook-CPU-Portable.zip`** — архив всей папки `Zvukbook-CPU`.
- `SHA256SUMS.txt`, `release-manifest.json`, `README.txt` — контрольные суммы
  и сведения об этом выпуске.

В CPU-поставке остаются все голоса Silero, модель, PyTorch CPU, русский OCR,
FFmpeg, DjVuLibre, WebView2 и MSVC. Удалён только CUDA-runtime: ускорения NVIDIA
в этой версии нет даже на ПК с видеокартой. Получателю не нужны установки
Python/PyTorch/OCR и подключение к интернету для работы с книгами.
По размерам компонентов прежнего полного ZIP ожидается около **0,8–0,9 GB**
на каждый сжатый артефакт; фактический размер будет напечатан после упаковки.
В локальной рабочей копии CPU-артефакты уже созданы; функциональная приёмка на другом ПК остаётся за пользователем. Размер нового выпуска определяется его упаковкой.
Распакованное приложение и кэш сборки занимают больше места, чем архив.

Установщик ставит CPU-версию отдельно в
`%LOCALAPPDATA%\Programs\Zvukbook-CPU`, с ярлыком **«Звуккниг CPU»**.
Полная установленная версия и её файлы сохраняются. Portable распаковывай
в отдельную папку: не накладывай CPU-архив поверх полного комплекта.
В обеих версиях библиотека общая — `%LOCALAPPDATA%\Zvukbook`; открывай одну
версию за раз. Если в настройках остался GPU от полной версии, окно попросит
явно подтвердить CPU перед озвучкой. Выбора NVIDIA в CPU-версии нет.

Для частых правок интерфейса/ядра можно не перепаковывать архивы:

```bash
powershell.exe -NoProfile -File ./scripts/build-windows.ps1 -Edition cpu
```

Затем вручную открой
`.local-data\windows-x64\dist-cpu\Zvukbook\Zvukbook.exe`.
Эта короткая команда обновляет рабочую папку; для передачи другу снова нужна
команда с `-Release`. Неизменные CPU-зависимости используются из кэша,
CUDA-окружение не подготавливается и не копируется. Общий кэш защищён от
одновременных сборок. Полная сборка по-прежнему вызывается через
`build-release.cmd`, без `-Edition cpu`, и сохраняется в `release`.

Перед сборкой CPU-папки требуется **8 GiB** свободного места, затем перед
упаковкой ещё проверяется остаток **8 GiB**. На первом проходе учти место,
которое займёт новая отдельная папка приложения: оно расходуется до второй
проверки. Порог полной сборки остаётся **15 GiB**. Первичная подготовка CPU
при отсутствии кэша требует интернет и может занять дополнительное место.
Скрипт собирает файлы, но не запускает установщик, приложение или тесты.

## Обычный цикл разработки

1. Закрой окно Звуккниг.
2. Внеси изменения в проект или попроси агента их внести.
3. Дважды щёлкни `D:\zvukbook\build-windows.cmd` или выполни в PowerShell:

```powershell
Set-Location D:\zvukbook
& .\scripts\build-windows.ps1
```

4. Снова запусти `.local-data\windows-x64\dist\Zvukbook\Zvukbook.exe`.

Скрипт собирает Go/Wails и копирует актуальные Python/HTML/CSS/JS в комплект.
При неизменных lock-файлах большие runtime повторно не устанавливаются и не
копируются. Работающее приложение блокирует пересборку. Тесты и приложение
сборочный скрипт сам не запускает.

Чтобы собрать также установщик и ZIP, дважды щёлкни `build-release.cmd` или:

```powershell
& .\scripts\build-windows.ps1 -Release
```

Архивирование нескольких гигабайт дольше обычной пересборки интерфейса.
Команда компилирует установщик, но **не запускает его и приложение**.

## Настройки и зависимости

При первом запуске окно предлагает устройство озвучки. Доступная NVIDIA
предварительно определяется по системному CUDA-драйверу и возможности выделить
бюджет памяти; подходящий вариант предлагается, пользователь сохраняет выбор.
Кнопка **«Устройство озвучки»** меняет его между задачами без терминала и
пересборки. Настройка хранится в `%LOCALAPPDATA%\Zvukbook\desktop-settings.json`.
Если ранее выбранная NVIDIA больше недоступна, снова требуется явный выбор.

Для адресной диагностики остаётся явный CPU-запуск из PowerShell:

```powershell
& .\.local-data\windows-x64\dist\Zvukbook\Zvukbook.exe --device cpu
```

Исходный профиль в `config/windows-desktop.json` — CPU; новый пользователь
подтверждает выбор в окне. CUDA не переключается на CPU при ошибке.
Другие модели и ускорение AMD/Intel пока не реализованы.

Для пересборки нужны Go ≥ 1.25.0 и CPython **3.12.10 x64** с pip/venv.
Найдены и использованы Go 1.25.3 и `C:\Python312\python.exe`. Другой путь:

```powershell
& .\scripts\build-windows.ps1 -Python 'C:\путь\к\Python312\python.exe'
```

Первичная подготовка полной сборки требует интернет и не менее 15 GiB свободного места;
зависимости закреплены SHA-256 в `requirements/windows-*.lock`,
`requirements/windows-probe/` и `config/windows-downloads.json`.
Кэш, Windows-venv и комплект находятся только в `.local-data/windows-x64/`.
Linux `.local-data/books-renderer/.venv` не используется. Для новой машины
сборки подготовь модель командой `& $ZvukbookPython .\scripts\prepare-model.py`,
где переменная содержит путь к CPython. Она скачивает официальные веса и проверяет SHA;
сборщик не заменяет их другой версией. Первый запуск описан в [README](../README.md).

В готовом комплекте системные Python/Go/Node не нужны. WebView2 Fixed Version
156.0.4314.58 x64 и Visual C++ 14.44.35211 включены в поставку; версии и SHA
закреплены. Обновление Fixed WebView2 выполняется новым выпуском приложения,
он не обновляется автоматически. Лицензии сохранены в комплекте.
Для установщика используется распакованный архив Tools.InnoSetup 7.1.0,
отдельно устанавливать компилятор на машине сборки не требуется.

## Ограничения и диагностика

Одна тяжёлая задача, CPU hard cap 25%, адаптивный commit-бюджет:
512 MiB–2 GiB для импорта, 1–2 GiB для CPU TTS, 3–6 GiB для CUDA TTS.
Это потолок committed memory дерева, а не постоянно занятая RAM.
CPU использует 1–2 потока (на малой RAM — один), фрагменты до 160 знаков и
небольшую паузу между ними. OCR на малой RAM получает меньшие изображения:
PDF до 160 dpi / 6 млн пикселей, DjVu до 2000×2600. Перед озвучкой текст
скана нужно просмотреть: меньшие изображения могут изменить качество OCR.

Ориентир для слабого CPU-ноутбука — Windows 10 19041+/11 x64, 4 GiB RAM и
выше; фактически должно остаться хотя бы 1 GiB бюджета обработчика сверх
резерва Windows. На 4 GiB может потребоваться закрыть браузер/другие программы.
Это проектный ориентир, а не подтверждённая измерениями минимальная конфигурация.
Скорость не гарантируется; на слабом CPU рендер может быть медленнее записи.
Жёсткого Windows-порога 8 GiB свободной RAM больше нет.

Резерв RAM CPU/import: `max(512 MiB, total/6)`, commit:
`max(512 MiB, commit_limit/12)`. Для CUDA соответственно
`max(1 GiB, total/4)` и `max(1 GiB, commit_limit/10)`.
Бюджет ограничен минимумом потолка профиля, половины общей RAM, 80% доступной
RAM, остатка RAM и commit после резервов. Он фиксируется до запуска и не растёт.

AppContainer без сетевых capabilities, только вход/выход текущей задачи.
Проверяются RAM/commit/VRAM/диск. При нехватке ресурса требуется явный повтор;
лимиты автоматически не растут. Время постановки задачи включает выдачу и
снятие доступа к комплектным инструментам.

При ошибке открой **«Диагностика»** в карточке задачи: там будут последний этап,
тип ошибки, WinError/errno, PID и код завершения (если обработчик успел их
сохранить), сообщения конвертера и полный путь к журналам. После ошибки импорта
можно нажать **«Извлечь текст заново»** прямо в карточке; загрузка того же файла
повторно не нужна. После остановки заголовок показывает состояние ошибки,
а не только оставшийся процент обработки.

Для короткой блокировки JSON-файла Windows добавлены ограниченные повторы
атомарной замены: только WinError 5/32/33, всего до 7 попыток, суммарные паузы
0,785 с. Повторяется запись уже готовых байтов, модель/задача не перезапускается.
Старый целый JSON сохраняется до успешной замены. `json_replace_retry`,
`json_replace_recovered`, `json_replace_failed` в worker.log показывают ход
замены. Если блокируется именно служебный **progress.json**, после этих
попыток рендер продолжает текущую главу. Запись прогресса откладывается до
следующего обычного обновления, не раньше чем через 2 с; отдельного цикла
повторного запуска задачи/модели нет. В журнале — `progress_write_deferred`
и `progress_write_recovered`. Процент в интерфейсе временно может отставать.

Каждая готовая глава имеет отдельный `ready-0001.json` и т. д.; manager
проверяет и публикует её независимо от progress.json. Итог пишется в
`result.json`, ошибка — в `failure.json`. Manager также откладывает чтение
заблокированного прогресса, сохраняя контроль отмены/ресурсов. По завершении
приоритет у result/failure, затем у progress. Запрет сохранения самих MP3,
обязательных данных, нехватка диска/памяти и настоящие ошибки модели остаются
ошибками. Конкретный процесс, удерживавший файл при прежнем сбое, не установлен.
После остановки используй **«Выделить неозвученные» → «Озвучить выделенные»**;
готовые главы остаются, незавершённая глава начнётся заново.

Журналы каждой задачи: `%LOCALAPPDATA%\Zvukbook\library\jobs\<id>\`:

- `worker.log` — этапы чтения, страницы PDF/DjVu, запуск/окончание DjVu/Tesseract/
  FFmpeg, очистка, главы, модель/озвучка и ошибка со стеком мест вызова.
- `manager.log` — приём файла, очередь, запрос запуска, завершение и публикация.
- `host.log` — подготовка AppContainer, бюджет памяти, PID, запуск, отмена и
  снятие временных доступов; остаётся и при ошибке до запуска Python worker.
- `host-report.json` — итог ресурсов/ограничений, код завершения и сведения о
  сохранении worker.log. Если журнал длиннее 2 MiB, сохраняется его конец с
  последней ошибкой, а усечение отмечается в отчёте.
- `failure.json` — отдельный отчёт об ошибке, если worker смог его записать.
  Он не зависит от возможности заменить `progress.json`.

Новые этапные записи — UTF-8, одна JSON-запись на строку, с временем UTC;
обычный вывод инструментов тоже может находиться в `worker.log`. Тексты глав,
полные аргументы команд и токены в этапные записи не добавляются. При этом
сообщения внешних инструментов/исключений могут содержать имена файлов и другие
личные сведения: просматривай журналы перед передачей.
Ошибка запуска backend — `%LOCALAPPDATA%\Zvukbook\backend\worker.log`.

Для пересборки из Bash-терминала VS Code в корне проекта:

```bash
powershell.exe -NoProfile -File ./scripts/build-windows.ps1
```

Эта команда не запускает приложение и проверки. После пересборки открой
обновлённый EXE из `dist\Zvukbook`, затем явно повтори извлечение текста.

### Подготовка текста для Silero

В блоке голоса добавлено окно **«Произношение, замены и ударения»**: списки
ручных замен и ударений, изменение/удаление, быстрый редактор главы и
предпросмотр речи без модели. Ввод ударения: `злодЕй`/`злоде́й`/`злод+ей`.
Замены работают во всех главах текущей книги и хранятся в её канонической
версии, исходник от них не меняется. После удаления правила чтение
пересчитывается; только затронутым главам нужна новая озвучка.
Правила сохраняются при повторном извлечении текста. Подробности и ограничения —
[books-start.md](books-start.md#произношение-замены-и-ударения).

Автоэвристика расширена единицами (`м2`, `м²`, `кв. м`, `м3`, `км/ч`, масса,
время и др.) и обычными графическими сокращениями. Единицы после цифр
согласуются по числу; неоднозначные даты/инициалы не заменяются глобально.
Нормализация речи — версия 4, импорт/очистка исходника остаются версии 5.
Ручные `+` вставляются только после обычной очистки и сохраняются при делении
на фрагменты и ограниченном markup fallback. SSML/эмфаза из книг не разрешены.
Изменено общее ядро и интерфейс; для полной/CPU-сборки нужна пересборка,
в Linux — перезапуск сервера. Агент новые правила/синтез не запускал.

Для уже импортированной книги нажми **«Очистить текст для озвучки без OCR»**.
Кнопка расширена: кроме примечаний/звёздочек убирает невидимые символы,
изолированные короткие номера страниц на краях глав PDF/DjVu и колонтитулы,
подтверждённые повторениями или известными заголовками. Удалённые номера и
фрагменты колонтитулов остаются в отчёте исключений. Распознанный заголовок,
склеенный с прозой, удаляется только как известный префикс, продолжение остаётся.
Неоднозначные четырёхзначные числа (возможные годы) внутри существующего текста
сохраняются; голые числа в TXT не считаются номерами страниц автоматически.
Изменённым главам понадобится новая озвучка; прочие готовые MP3 сохраняются.

Перед синтезом отдельно готовится произносимая версия: скрытые Unicode-символы,
кавычки/скобки и служебная разметка удаляются, содержимое внутри них остаётся;
тире превращаются в паузы. Числа проговариваются словами, включая десятичную
дробь, знак минуса, научную запись и распространённые «млн/млрд/трлн»;
цифры в названии изотопа также сохраняются в речи. Безгласные сокращения вроде
«НБВ» читаются по буквам, латиница транслитерируется, греческие буквы получают
русские названия. Это детерминированная нормализация, без дополнительной модели,
пакетов и сетевых запросов. Склонение числительных/единиц и иностранные имена
могут потребовать ручной правки; исходные цифры в редакторе остаются цифрами.
Необходимость внешней нормализации чисел также описана в
[ответе автора Silero](https://github.com/snakers4/silero-models/discussions/221).

Смешанные OCR-слова исправляются отдельно: похожие латинские буквы внутри
кириллического слова (`HБВ`, `cостоит`) заменяются русскими аналогами. Целиком
латинские названия, формулы `CO2`/`H2O` и римские номера сохраняются на этом этапе
и получают произносимую форму позже. OCR по-прежнему использует Tesseract rus;
жёсткий запрет латиницы при распознавании не вводится. В озвучку проходят
русские буквы, пробелы и разрешённая пунктуация; при нарушении этой проверки
сообщение укажет сам символ, его Unicode-код и название.

Исправлена ошибка раскрытия `НБВ1`: словарь названий букв использует строчные
ключи, обращение к нему теперь приводит букву к нижнему регистру. Алфавит
сокращений берётся из того же словаря. Версии: импорт/очистка 5, речь 3.
Регрессионные случаи для `НБВ1`, смешанных алфавитов, чисел и проверки символов
добавлены в `tests/test_speech.py`; они используют подставной генератор без
PyTorch/OCR/сервера и не запускаются сборочным скриптом. Агент их не запускал.

Ошибки TTS теперь содержат тип и функцию/строку исходного исключения, даже
когда Silero выдала пустой ValueError. В worker.log сохраняется цепочка причин
без текста фрагмента и locals, а в диагностике — номер и длина фрагмента после
подготовки. Непонятный содержательный фрагмент не считается успешно озвученным.
Единственный повтор после известной ошибки разметки остаётся ограниченным;
CUDA/OOM и другие ошибки ресурсов не превращаются в пропуск текста или CPU fallback.

Эти изменения ещё требуют ручной проверки владельцем после пересборки.

Linux по-прежнему запускается отдельно:

```bash
bash scripts/start-local.sh
```

Адрес лаборатории: `http://127.0.0.1:8767/`. Сборка EXE ей не нужна.

История локальных проверок владельца не входит в публичный репозиторий.
Сборка не подтверждает функциональную приёмку нового выпуска: запуск, OCR и
звучание пользователь проверяет на своей машине.
