# Звуккниг · Zvukbook

**Локальная мастерская русскоязычных аудиокниг для Windows и Linux.** Загрузи книгу, проверь текст, выбери голос и получи MP3 по главам. Озвучка — Silero, распознавание сканов — Tesseract `rus`. Текст книг и готовое аудио остаются на твоём компьютере.

В репозитории публикуются **исходники и инструкции**. Установщики, portable-архивы, модель и зависимости не хранятся в GitHub: их нужно подготовить и собрать локально. Интернет нужен для первоначальной загрузки зависимостей и весов; обработка книг после подготовки работает без облачных TTS/OCR.

[Windows: запуск](#windows-запуск-из-исходников) · [Windows: portable](#windows-сборка-portable) · [Linux](#linux-локальная-лаборатория) · [Интерфейс](#как-пользоваться) · [Данные](#где-хранятся-книги-и-mp3) · [Лицензия](#лицензия)

## Возможности

- TXT, FB2/FB2.zip, EPUB, DOCX, PDF, DJVU/DJV. Для PDF/DjVu — текстовый слой или русский OCR. Старый DOC поддержан только Linux-адаптером через LibreOffice.
- Галерея с поиском, состояниями и обложками. Для FB2/EPUB приложение ищет встроенную обложку, для PDF/DJVU пробует первую страницу; свою картинку можно загрузить вручную. Если изображение не удалось получить, показывается логотип приложения.
- Редактор глав, очистка служебного текста и сносок, отчёт исключений.
- Пять голосов Silero: `xenia`, `kseniya`, `baya`, `aidar`, `eugene`; скорость 0,75–1,75× и высота голоса.
- Подготовка чисел, единиц и сокращений к речи, ручные замены и ударения для каждой книги.
- Один текущий MP3 на главу. Исправление одной главы сохраняет готовность остальных; после остановки можно выделить только неозвученные.
- Прослушивание, сохранение отдельных MP3, открытие аудиопапки и экспорт ZIP с manifest/обложкой.
- Windows-окно на Go/Wails, выбор CPU/NVIDIA, ограничения ресурсов и AppContainer. Linux-сервер с браузерным интерфейсом, cgroup и bubblewrap.
- Светлая/тёмная тема с запоминанием выбора.

## Две Windows-комплектации

| | CPU — облегчённая | Полная |
| --- | --- | --- |
| Озвучка | Только процессор | Процессор или совместимая NVIDIA |
| ML-окружение | Python + **PyTorch CPU**, без CUDA | Раздельные CPU- и CUDA-runtime |
| Голоса, OCR, редактор, обложки | Все основные функции | Все основные функции |
| Python, OCR и WebView2 у получателя | Входят в комплект | Входят в комплект |
| Драйвер NVIDIA | Не нужен | Нужен только для GPU-режима |
| Установщик | `Zvukbook-CPU-Setup.exe` | `Zvukbook-Setup.exe` |
| Portable | `Zvukbook-CPU-Portable.zip` | `Zvukbook-Portable.zip` |

**CPU-версия содержит PyTorch для процессора.** Из неё исключена тяжёлая CUDA-часть, а нейросетевая озвучка сохранена. На слабом процессоре подготовка книги может идти медленнее её прослушивания.

Целевая система: **Windows 10 19041+ / Windows 11, x64**, локальный NTFS-диск. Windows ARM64 и ускорение AMD/Intel не заявлены. Ориентир CPU-профиля — 4 GiB общей RAM и свободный бюджет сверх резерва Windows; это не подтверждённый минимум для любого ПК. Приложение проверяет доступные ресурсы и может отказать в старте задачи. Оставляй минимум 5 GiB свободного места сверх приложения, книг и MP3.

## Windows: запуск из исходников

Команды выполняются **на Windows**, из PowerShell в корне скачанного проекта. Можно клонировать репозиторий или выбрать на GitHub **Code → Download ZIP** и распаковать исходники.

### 1. Подготовь инструменты сборки

- [Go](https://go.dev/dl/) **1.25.0 или новее**; предыдущая Windows-сборка использовала 1.25.3. Команда `go` должна быть в PATH.
- [CPython **3.12.10 x64**](https://www.python.org/downloads/release/python-31210/) с pip и venv. Эта точная версия проверяется сборщиком.
- Системный `curl.exe`, интернет для первичной подготовки и свободное место. Проверяемый порог CPU-сборки — 8 GiB, полной — 15 GiB; подготовка кэша и упаковывание потребуют дополнительного места.

Node.js/npm и отдельный Wails CLI для текущего сборочного скрипта не требуются. Go-зависимости берутся из `desktop/go.mod`/`go.sum`, Windows-пакеты — из lock-файлов с SHA-256. Скрипт сам готовит приватные runtime, FFmpeg, Tesseract, русский tessdata, DjVuLibre, WebView2 и app-local Visual C++ DLL.

### 2. Подготовь модель

Ниже `C:\Python312\python.exe` — пример пути к установленному CPython **3.12.10 x64**. Если Python установлен в другом месте, измени переменную:

```powershell
$ZvukbookPython = 'C:\Python312\python.exe'
& $ZvukbookPython .\scripts\prepare-model.py
```

Скрипт скачивает **Silero v5_6_ru** из официального источника, проверяет SHA-256 и сохраняет лицензию/manifest в `.local-data\books-renderer\models\silero-v5_6_ru\`. Уже имеющийся правильный файл используется повторно. Файл с другим SHA не заменяется молча. Модель и сервер эта команда **не запускает**.

### 3. Собери и открой рабочую папку

Для облегчённой CPU-версии:

```powershell
& .\scripts\build-windows.ps1 -Python $ZvukbookPython -Edition cpu
& .\.local-data\windows-x64\dist-cpu\Zvukbook\Zvukbook.exe
```

Для полной версии CPU + NVIDIA:

```powershell
& .\scripts\build-windows.ps1 -Python $ZvukbookPython
& .\.local-data\windows-x64\dist\Zvukbook\Zvukbook.exe
```

Первый проход скачивает и устанавливает закреплённые зависимости в отдельный Windows-кэш; это может занять время и несколько гигабайт. Следующие сборки повторно используют неизменные runtime. Если скачанный файл изменился и SHA не совпал, сборка останавливается — не отключай проверку хеша.

При первом открытии сохрани выбор устройства в окне **«На чём озвучивать книги»**. В CPU-сборке доступен только процессор; в полной можно выбрать NVIDIA. **«Устройство озвучки»** меняет выбор между задачами. При ошибке CUDA приложение не переключается на CPU незаметно.

Закрытие окна останавливает backend и обработчики. Собранный `Zvukbook.exe` запускается из своей папки **вместе со всеми ресурсами**; один EXE переносить недостаточно.

### После изменения кода

Закрой приложение, повтори соответствующую команду сборки и открой EXE заново. Сборщик обновляет Python/HTML/CSS/JS в комплекте; не запускает автоматически приложение, установщик или функциональные тесты. Библиотека хранится отдельно и при пересборке не удаляется.

Если CPython находится по стандартному для этого проекта пути `C:\Python312\python.exe`, полную рабочую папку также можно собрать двойным щелчком по `build-windows.cmd`.

## Windows: сборка portable

Собирать нужно **в Windows x64**: скрипт использует Windows Python и инструменты Windows. Обычный запуск Linux-скрипта или PowerShell под Linux не соберёт этот комплект. Закрой Звуккниг и подготовь инструменты и модель, как описано выше.

Для стандартного пути Python `C:\Python312\python.exe` можно дважды щёлкнуть в корне проекта:

- **`build-cpu-portable.cmd`** — облегчённый архив только для процессора.
- **`build-portable.cmd`** — полный архив для процессора и NVIDIA.

Либо выполни в PowerShell, указав свой путь к Python через `$ZvukbookPython`:

```powershell
$ZvukbookPython = 'C:\Python312\python.exe'  # Измени путь, если Python установлен в другом месте.

# Облегчённый portable для CPU.
& .\scripts\build-windows.ps1 -Python $ZvukbookPython -Edition cpu -Portable

# Полный portable для CPU + NVIDIA.
& .\scripts\build-windows.ps1 -Python $ZvukbookPython -Edition full -Portable
```

Можно собрать только нужную комплектацию. Версия выпуска берётся из [config/windows-release.json](config/windows-release.json).

| Результат | Каталог |
| --- | --- |
| `Zvukbook-CPU-Portable.zip` | `.local-data/windows-x64/portable-cpu/` |
| `Zvukbook-Portable.zip` | `.local-data/windows-x64/portable/` |
| `SHA256SUMS.txt`, `release-manifest.json`, `README.txt` | Рядом с файлами каждой комплектации |

`-Portable` сначала обновляет рабочую папку, затем создаёт ZIP без установщика и без компилятора Inno Setup. Старый режим `-Release` и его отдельные каталоги сохранены: он по-прежнему собирает установщик и ZIP. Упаковка дольше обычной пересборки; перед ней проверяется дополнительный резерв места. Полученные файлы остаются локально и исключены из Git.

### Использование самостоятельно собранного выпуска

**Portable:** распакуй **всю** папку из ZIP на локальный NTFS-диск в записываемое место и открой `Zvukbook.exe`. Не запускай его внутри архива и не накладывай CPU-архив поверх полной версии. Portable относится к папке программы; библиотека по умолчанию всё равно хранится в профиле пользователя.

После сборки получателю не нужны системные Python/Go/OCR/PyTorch, отдельная установка WebView2 и интернет для обработки книг. CPU-версия содержит CPU-сборку PyTorch, но не содержит CUDA-окружение. Для GPU требуется подходящий NVIDIA-драйвер. Полная и CPU-версии используют одну пользовательскую библиотеку, поэтому запускай одну из них за раз. Сам `Zvukbook.exe` тоже не подписан, поэтому Windows или антивирус могут предупредить и при запуске portable.

Подробнее о Windows-процессах, ресурсах и диагностике — [docs/windows-build.md](docs/windows-build.md).

## Linux: локальная лаборатория

Linux-режим запускается из исходников в браузере и не требует сборки Go/Wails или Windows EXE. Можно править Python-код и перезапускать тот же сервер. Другая модель может требовать изменения адаптера и manifest: произвольные веса с неизвестным API не становятся совместимыми автоматически.

Текущий Linux-профиль — **x86_64, NVIDIA CUDA**, Python 3.12, пользовательский systemd с cgroup v2 и bubblewrap. Linux CPU-режим в текущем скрипте не реализован. Linux- и Windows-окружения раздельные.

### Подготовка нового окружения

Пример системных пакетов для **Ubuntu 24.04 / Linux Mint 22**:

```bash
sudo apt update
sudo apt install python3.12 python3.12-venv bubblewrap ffmpeg \
  tesseract-ocr tesseract-ocr-rus djvulibre-bin
```

Для старого DOC дополнительно нужен `libreoffice-writer`. NVIDIA-драйвер должен быть установлен в системе отдельно.

В корне проекта, **только при первой подготовке новой копии**:

```bash
python3.12 -m venv .local-data/books-renderer/.venv
.local-data/books-renderer/.venv/bin/python -m pip install -r requirements.lock
.local-data/books-renderer/.venv/bin/python scripts/prepare-model.py
```

Если окружение и модель уже подготовлены, пропусти этот шаг. `requirements.lock` относится к Linux; Windows lock-файлы сюда не устанавливаются. Первичная подготовка требует интернета, CUDA-библиотеки занимают несколько гигабайт.

### Запуск

Из терминала обычной графической сессии, **без sudo**:

```bash
bash scripts/start-local.sh
```

Открой **[http://127.0.0.1:8767/](http://127.0.0.1:8767/)**. Остановка — **Ctrl+C**. Другой порт:

```bash
bash scripts/start-local.sh --port 8768
```

Запускай через этот скрипт: прямой `python zvukbook.py` не создаёт необходимые ресурсные ограничения. После правок Python/интерфейса останови сервер, запусти снова и обнови страницу через Ctrl+F5.

Linux-профиль ограничивает дерево до трёх CPU-эквивалентов, RAM high 6 GiB / hard 8 GiB, swap=0. Перед тяжёлой задачей нужны не менее 8 GiB доступной RAM; перед CUDA-синтезом — 2 GiB свободной VRAM. Это текущие защитные пороги, а не обещание постоянного потребления.

## Как пользоваться

### 1. Добавь и проверь книгу

Кнопка **«Помощь»** в верхней панели открывает руководство и ответы на частые вопросы прямо в приложении. Наведи указатель на кнопку, чтобы увидеть краткое пояснение её действия.

Слева выбери файл до **100 MiB** и нажми **«Загрузить и подготовить текст»**. В галерее появится книга, после извлечения — главы. Уже загруженный одинаковый файл не дублируется.

Для PDF/DjVu сначала используется пригодный текстовый слой, иначе — русский OCR. Результат зависит от скана, колонок и вёрстки: открой **«Проверить текст»** у главы до полной озвучки.

В разделе **«Извлечение текста и очистка PDF/DJVU»** доступны принудительный OCR, колонтитулы, оглавление/служебные строки, литература, редакторские примечания и кодировка TXT. Для неверно определённой кодировки выбери UTF-8 или Windows-1251 и повтори извлечение.

**«Извлечь текст заново»** берёт оригинал: ручные исправления глав заменятся. Это отдельное действие от очистки текущего текста.

### 2. Очисти текст и настрой произношение

**«Очистить текст для озвучки без OCR»** работает с текущей редакцией: убирает узнаваемые примечания/звёздочки, невидимые символы, подтверждённые номера страниц и колонтитулы. Исключения сохраняются в отчёте. Эвристики могут ошибаться — просматривай результат; неизменённым главам новая озвучка не нужна.

**«Произношение, замены и ударения»** открывает правила текущей книги:

- **Замены** действуют на целые слова/фразы без учёта регистра: например `СССР` → `эс эс эс эр`. Пустая замена удаляет совпадение из текста выбранных глав.
- **Ударения:** `злодЕй`, `злоде́й` или `злод+ей`. Каждая словоформа задаётся отдельно: правило для `злодей` не описывает автоматически `злодея`.
- Выбери главы: по умолчанию отмечены все. **«Применить правила к выбранным главам»** записывает замены и ударения в подготовленный текст и показывает число изменений. Загруженный исходный файл сохраняется. Ударение в тексте отмечается знаком над гласной; в предпросмотре речи — `+` перед ней.
- Нажми на число изменений и выбери нужное место в списке. Можно исправить падеж в тексте и нажать **«Сохранить правку главы»**, не применяя правила повторно. Список относится к последнему применению и доступен до закрытия окна. Изменённые главы нужно переозвучить.
- Правила сохраняются для книги, но их удаление не отменяет уже записанные в текст изменения. Повторное извлечение возвращает текст из исходного файла и заменяет ручные исправления; правила после этого можно применить снова.

Числа, распространённые единицы/сокращения и смешанные OCR-слова дополнительно нормализуются перед синтезом. Формулы, склонения и иностранные имена могут требовать ручной правки.

### 3. Выбери голос и создай образец

Выбери диктора, скорость и высоту. Нажми **«Создать короткий образец»**, послушай его и только затем озвучивай книгу целиком. Это звуковая проба, в отличие от текстового предпросмотра произношения.

### 4. Озвучь и продолжай после остановок

Нажми **«Выделить неозвученные» → «Озвучить выделенные»**. Результаты появляются по мере готовности, в тех же строках глав.

Правка одной главы не сбрасывает остальные MP3. После ошибки исправь проблемный текст и снова выбери неозвученные; незавершённая глава начнётся заново.

**Любая явно выбранная готовая глава озвучивается повторно.** Новый успешный MP3 заменяет прежний, аудиоархив версий не создаётся. **«Выделить все»** и **«Озвучить всю книгу заново»** предназначены для полной переозвучки. **«Остановить»** завершает задачу, сохраняя опубликованные главы.

Если Windows не даёт заменить файл, открытый внешним плеером, закрой его и нажми **«Повторить публикацию MP3»**. Уже созданный результат будет опубликован без повторного TTS.

### 5. Слушай, сохраняй и меняй оформление

У готовой главы есть **«Слушать»** и **«MP3»**. **«Открыть папку MP3»** показывает каталог книги; ZIP экспортирует текущие готовые главы, manifest и имеющуюся обложку. Во время активной обработки ZIP может быть недоступен.

**«Название, автор и обложка»** позволяет заменить метаданные и загрузить JPG/PNG/WebP до 16 MiB и 20 млн пикселей. Найденная или выбранная обложка сохраняется как `cover.jpg` рядом с MP3 и в ZIP, внутрь MP3 не встраивается. Для PDF/DJVU используется первая страница: это предположение, она может оказаться титульным листом. Если сохранённой обложки нет, в приложении показывается логотип; отдельный `cover.jpg` с ним не создаётся. Уже сохранённые обложки PDF/DJVU также отображаются. Пользовательская обложка сохраняется при повторном извлечении текста. Изменение названия/автора не переносит уже назначенную аудиопапку.

**«Тёмная тема»** в верхней панели сохраняет выбор. **«Удалить»** после подтверждения удаляет книгу, её исходник, подготовленные тексты, все MP3/обложку и задачи. Это отличается от удаления установленной программы, которое сохраняет библиотеку.

## Где хранятся книги и MP3

| Данные | Windows | Linux |
| --- | --- | --- |
| Библиотека: SQLite, оригиналы, тексты, задачи | `%LOCALAPPDATA%\Zvukbook\library\` | `.local-data/books-renderer/library/` |
| Настройка устройства | `%LOCALAPPDATA%\Zvukbook\desktop-settings.json` | Текущий профиль Linux CUDA |
| Окружение и модель разработчика | `.local-data/windows-x64/`; исходная модель — `.local-data/books-renderer/models/` | `.local-data/books-renderer/` |

Новые MP3 располагаются в `library/mp3/Название — Автор [ID]/`, файлы глав — `0001.mp3`, `0002.mp3`…; образец — `0000.mp3`, обложка — `cover.jpg`. Старые книги могут использовать прежний путь; точный каталог показан на странице и открывается отдельной кнопкой.

Резервная копия — весь каталог библиотеки **после остановки приложения**. Пересборка/обновление программы не заменяет личную библиотеку. Windows не открывает Linux-библиотеку автоматически; для переноса сначала сделай копию. Не коммить книги, SQLite, MP3 и журналы.

## Ограничения и частые вопросы

**Можно ли слушать с телефона через этот сервер?** Сейчас приложение готовит аудио локально. Готовые MP3 можно перенести на телефон. Серверный доступ с разных устройств и история Android — отдельное развитие, не текущая функция.

**Почему не появился голос NVIDIA?** В CPU-комплектации ускорения нет. Для GPU нужна полная сборка, совместимая NVIDIA, драйвер и свободная VRAM. Автоматического перехода на CPU после ошибки нет.

**Почему задача остановилась из-за памяти?** Windows рассчитывает бюджет CPU/RAM/commit/VRAM перед задачей и оставляет резерв системе; CPU дерева ограничен 25%, одна тяжёлая задача за раз. На Linux действуют отдельные фиксированные квоты. Освободи ресурс и повтори явно; повышать лимиты автоматически приложение не будет. Жёсткая доля загрузки GPU не гарантируется лимитом VRAM.

**Linux пишет `FileNotFoundError` для `canonical/...json`.** Команда запуска правильная: в SQLite есть запись, но файл подготовленного текста недоступен. Обработка такого случая исправлена: библиотека должна открыться с ошибкой отдельной книги. Если оригинал сохранился, повтори извлечение; иначе восстанови каталог из резервной копии или удали недоступную запись через галерею и загрузи исходник заново. Сам сервер не восстанавливает потерянные файлы из ничего.

**Где найти ошибку обработки?** В Windows открой **«Диагностика»** в карточке задачи. Там указаны этап, причина и пути журналов. Текст ошибки/внешнего инструмента может содержать личные пути — просматривай журнал перед отправкой. Логи, библиотеку и `.env` не публикуй.

**Что уже проверено?** На Windows 10 x64 ранее проходили короткие CPU/CUDA-пробы и основные сценарии прототипа. Это не подтверждение всех новых функций на любом ПК: длительный OCR, слабые ноутбуки, свежие правила речи и Linux после Windows-адаптации требуют собственной проверки. Сборочный скрипт не является функциональной приёмкой.
